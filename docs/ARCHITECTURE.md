# Архитектура Desktop Island

```
┌───────────────────────────── Фронтенд (React + TS, Vite) ─────────────────────────────┐
│ окно island (всегда)                      │ окно settings (по требованию, уничтожается) │
│  Island ─ Compact / Notification / Expanded│  19 разделов, ленивые чанки                 │
│  карточки = React.lazy (отдельные чанки)   │                                             │
│  плагины = sandbox-iframe ⇄ postMessage    │                                             │
│  Zustand: app, island, media, sysmon, timers                                             │
└──────────────── invoke() / события ───────────────────────────────────────────────────┘
                          │ IPC (только локальные окна, capabilities/default.json)
┌──────────────────────────────── Бэкенд (Rust, Tauri 2, Tokio) ─────────────────────────┐
│ commands/   — тонкий слой IPC: валидация, вызов модулей, типизированные ошибки         │
│ core/       — AppState, настройки (+sanitize), окно/мониторы, горячие клавиши, профили, │
│               темы, подтверждения (токены), TaskSlot (управляемые фоновые задачи)       │
│ events/     — Event Manager: очередь уведомлений по приоритетам + активности           │
│ modules/    — music, system_monitor, clipboard, timers, notifications, game_mode,       │
│               applications; modules::reconcile() запускает/останавливает опросы        │
│ integrations/ — каталог приложений (уровни поддержки), ручное добавление, веб-окна ИИ  │
│ plugins/    — манифест, установка, права, протокол plugin://, брокер API, SDK          │
│ platform/   — types.rs (общие типы) + windows/* и linux/* (разные реализации)          │
│ database/   — SQLite, миграции, восстановление после повреждения                       │
│ logging/    — tracing (файлы с ротацией) + журнал событий в БД с лимитом               │
│ tray/       — трей, автозапуск                                                          │
└───────────────────────────────────────────────────────────────────────────────────────┘
```

## Ключевые решения

### Event Manager (`src-tauri/src/events`)
* `queue.rs` — чистая логика без таймеров (покрыта тестами): сортировка по приоритету, FIFO внутри приоритета, вытеснение критическим уведомлением, дедупликация (2 с), правила приложений (отключение / смена приоритета), DND, подавление в игровом режиме со счётчиком пропущенных, ограниченная история.
* `mod.rs` — таймер автоскрытия с «поколениями» (старые таймеры игнорируются), hold/release при наведении, рассылка `island://notification` и `island://activities`.
* Активности (музыка, таймеры, плагины) — отдельный канал: в компактной панели показывается одна, самая приоритетная (`pickCompact`). Уведомление не прерывает раскрытую карточку — оно ждёт сворачивания. Так музыка, Telegram и системный монитор не накладываются друг на друга и события не теряются.

### Ленивая работа модулей
`modules::reconcile()` вызывается при изменении настроек, видимости панели, игрового режима и набора открытых карточек (`ui_set_active_cards`). Каждый модуль держит `TaskSlot`:

| Модуль | Когда работает | Интервал |
|---|---|---|
| Музыка | модуль включён, панель видима, не игровой режим | 1 с (настраивается); 10 с при ошибках |
| Системный монитор | карточка открыта **или** включён показатель в компактной панели | 2 с (1–30 с); диски — раз в 30 с; батарея — раз в 5 циклов |
| Буфер обмена | история включена | Windows: 0.6 с (только `GetClipboardSequenceNumber`), Linux: 1.2 с |
| Уведомления ОС | модуль включён и API доступен; при недоступности — одна попытка | Windows 1.5 с; Linux — события D-Bus без опроса |
| Таймеры | модуль включён | спит до ближайшего срока (без опроса) |
| Игровой режим | всегда | 2 с (настраивается) |
| Мониторы | всегда | 3 с (сравнение сигнатуры конфигурации) |

Сэмплер системного монитора (sysinfo, NVML, PDH) создаётся при старте задачи и уничтожается при остановке — память освобождается.

### Окна
* **island** — прозрачное окно без рамки, поверх всех, без панели задач. Размер окна подгоняется под состояние острова: при увеличении окно растёт сразу (анимация внутри), при уменьшении — после анимации. Положение хранится как `relX` (доля ширины монитора) + `top` для каждого монитора отдельно; на Windows перемещение+изменение размера атомарное (`SetWindowPos`).
* **settings** — создаётся по требованию и уничтожается при закрытии (отдельный WebView не висит в памяти).
* **web-*** — мини-окна веб-сервисов с отдельным `data_directory` на сервис.

### Хранилище
SQLite (WAL). Таблицы: `settings` (раздел = строка JSON), `widget_settings`, `themes`, `profiles`, `hotkeys`, `plugins`, `plugin_settings`, `application_integrations`, `clipboard_history`, `timers`, `event_log`. Миграции по `PRAGMA user_version`. При старте — `quick_check`; повреждённый файл переименовывается в `island.db.corrupt-<ts>` и создаётся новый; если файл недоступен — база в памяти с предупреждением в UI. Динамические показатели в БД не пишутся; история уведомлений — только в памяти.

### Безопасность IPC
* Команды доступны только окнам `island` и `settings` (capabilities). Удалённые страницы (веб-окна ИИ) не получают IPC.
* Все команды асинхронные (не блокируют главный поток) и валидируют входные данные (`sanitize`, проверка путей/URL/идентификаторов).
* Опасные действия — двухшаговые: `power_request` выдаёт одноразовый токен на 60 с, `power_execute` требует его. Поддельный токен отклоняется (проверено смоук-тестом).
* CSP основного окна: `connect-src ipc:`; `frame-src plugin:`; `script-src 'self'`.

### Тесты
* Rust (`cargo test --lib`): очередь уведомлений, настройки, миграции и восстановление БД, журнал, токены подтверждения, манифест плагинов, темы, эвристика чувствительных данных, расчёт таймеров, распознавание игр, каталог интеграций, поиск приложений, изображения, URL.
* Фронтенд (`npm test`): форматирование, интерполяция медиа, разбор длительности, приоритет компактной панели.
* `desktop-island --selftest` — вызов всех системных адаптеров на реальной системе.
* `tests/smoke/*.js` — смоук-тесты IPC и системы плагинов в живом приложении (через CDP WebView2).
* `tools/linux-check` — проверка компиляции Linux-адаптеров с другой ОС.
